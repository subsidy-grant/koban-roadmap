# 自動入力の点検道具

「記入した内容が正しいか」を、記憶や前回の結果ではなく**その場で取り直して**確かめるための道具。
`documents.html` の自動入力を触ったら、出す前にここを通す。

## 先に立てるもの

```
cd D:\Claudecode\koban-roadmap
python -m http.server 8935
```

## 1コマンドで一次情報を取る

| やりたいこと | コマンド | 見るところ |
|---|---|---|
| **全様式を紙にして、目で見る**（1周まわす） | `python tools\sweep_render.py` | `sweep_out\<番号>_<様式>\` に 記入_*.png と 空_*.png。**41様式・150枚が約3分半で用意できる** |
| **開いた見た目が壊れていないか**（数枚を確かめる） | `python tools\render_check.py` | 「見た目の点検 OK」以外は出さない。**さらに `render_out\*.png` を必ず目で見る** |
| **入れすぎ・誤記入がないか**（57様式を一括） | `python tools\audit_autofill.py` | 最後の「疑わしい ○件」。**0件でなければ出さない** |
| **入れなかった欄の理由を型ごとに数える** | 上のあと `python tools\sweep_gaps.py` | **「見直す」の欄**。ここが増えていたら中身を見る |
| **入れ足りない欄がないか**（辞書の穴） | `python tools\sweep_labels.py` → `python tools\sweep_pick.py` | 「会社情報に関わりそうで、まだ読めていない欄名」。件数が増えていたら辞書に足す |
| **東京都の実物様式で崩れていないか** | `python tools\test_soui.py` | ALL OK 以外は出さない |
| **人材開発支援助成金の様式で崩れていないか** | `python tools\test_jinzai.py` | ALL OK 以外は出さない |
| **誤った中身を弾けるか**（最後の関所） | `python tools\test_guard.py` | ALL OK 以外は出さない |

`tools\soui\` は東京都中小企業振興公社の実物様式（配布元から取得）。
「記入例.xlsx」は**配布元が示す正解**なので、迷ったらこれと突き合わせる。

## いちばん大事：実際に開いて見る（render_check.py）

`render_check.py` は、記入したファイルを**本物のExcel／Wordで開いてPDFにし**、
紙になった姿を画像にする。ExcelとWordが入っている端末でだけ動く。
**空の様式も同じやり方で紙にして、`空_*.png` として並べて出す**。

中身（XML）だけを見る点検では、**次のどれ一つ見つけられなかった**：

- 法人番号が細いセルに押し込まれて潰れる（結合漏れ＋「縮小して全体を表示」）
- 所在地が「〒113」で切れて、住所がどこにも見えない
- ラベルの右の細い空きセルに書いてしまい、本当の記入枠の手前で切れる
- 1マス1桁のマス目の先頭に、番号を全部書いてしまう
- **縦につながったセル（vMerge の continue）に書き、どこにも表示されない**
- **1つの段落に項目が2つあり、最初の1つしか入らない**
- **右揃えの記名欄で、値を足したぶん項目名が左へ動き、行の頭が階段になる**
- **注記の「※」から書式を引き継ぎ、値だけ上付きの小さな文字になる**
- **値のぶん余白を詰めきれず、行末の項目が次の行へ回り込む**

どれも「開けば一目」。だから**必ず `render_out\*.png` を目で見ること**。
機械の判定（紙に出てこなかった値の一覧）は補助であって、目視の代わりにはならない。
機械は「入れた値が紙に出ているか」しか見ない。**位置・大きさ・折り返しは判定できない**。

### 空の様式と見比べる（`空_*.png`）

記入後だけを見ても「元からそうだったのか、こちらが崩したのか」は分からない。
2026-08-03、次の2つは**空の様式と並べて初めて**判断できた。

- 誓約書の項目名の位置ずれ → 空では4行きれいに揃っていた＝**こちらが崩していた**
- 様式第3号の「⑦企業規模＝大企業」 → 空でも選ばれていた＝**配布元の既定値**

配布元の作りをこちらの不具合と取り違えると、直す必要のないものを直して壊す。
逆も同じ。**迷ったら空の様式を紙にして並べる。**

### 150枚を1人で見るのは続かない（分担のしかた）

2026-08-03、41様式・152枚を8人で手分けして見て、6分で47件を挙げた。
そのときに効いた縛りを残す。

- **報告には「どの画像の、どの項目が、どう見えるか」を必ず書かせる。**
  「問題ありません」だけの報告は無効として、やり直す
- **記入後と空を必ずペアで渡す。** 片方だけでは「元からそうなのか」を判断できない
- **「崩れあり」と挙がったものは、必ず自分でその画像を開いてから直す。**
  伝聞で直さない。47件のうち5件は誤検出だった
  （業種の「分類項目」は様式側の計算式で、こちらは触っていなかった）
- 崩れが無かったぶんも、何枚見て何が入っていたかを書かせる。
  見ていないのに「問題なし」と書かれていないかは、そこで分かる

### 直したつもりが別のところを壊す

2026-08-03、位置をそろえようとして「上下の行と同じ形に結合する」を無条件に入れたところ、
狭い結合をまねてしまい、それまで右へはみ出して読めていた企業名が
「株式会社」で切れた。**直したあとは、直した箇所だけでなく同じ紙の全体を見ること。**

2026-08-04、**軽微な見た目を直そうとして、様式そのものを壊した**。
「記名欄が8mm左へずれる」を消そうとして幅の見積もりを作り直したところ、
文字の大きさの既定値を読む場所を1か所しか見ておらず、逆に幅を小さく見積もって
住所と氏名が行の途中で割れ、増えた行のぶんページ送りまで崩れた
（1ページ目の記述枠が2ページ目へ押し出された）。
**8mmのずれと、ページが崩れることは、重さが違う。**
見た目の小さな不満を消しにいくときほど、直す前と直した後で
「同じ紙が同じページ数に収まっているか」を先に確かめること。

同じ日、この2つも自分で作って自分で見つけた。

- 「行の端のセルにも書く」を入れた直後、表の**列見出し**に値を書き込んだ
  （下の行の同じ位置が空欄なら、そのセルは見出し、という条件を足して解消）
- 幅の既定値を入れた直後、「文書の既定」と「その段落の指定」を混同して、
  2行に分ける処理が効かなくなった

いずれも `diff_fills.py`（新旧の版で全ファイルの記入位置と値を突き合わせる）と
描画で見つかった。**コードを直したら、記入結果の差分を必ず見ること。**

    cd D:\Claudecode\koban-roadmap
    git show HEAD:documents.html > _old_documents.html
    python tools\diff_fills.py
    del _old_documents.html

「消えた」が出たら、意図した変更かどうかを必ず確かめる。
件数が同じでも入れる場所が変わっていることがあるので、
件数ではなく「場所と値」で突き合わせている。

## なぜこの2種類が要るのか

`audit_autofill.py` は**入れた欄**しか見ない。これだけだと「入れ足りない」穴は
永遠に見つからない（2026-08-03に実際に起きた）。
`sweep_labels.py` が**入れなかった欄**の側から見る。両方を回して初めて片側だけの
見落としが消える。

## 様式ごとに入る／入らないが分かれる、よくある原因

同じ項目でも、様式によって欄の書き方が違う。一つでも辞書に無いと**その様式だけ空欄**になる。

- 「④MAIL」と「④メール」（人材開発支援助成金の第1-1号と第4-1号で違う）
- 「事業者名」と「事業者名称」と「法人名又は屋号」
- 「電話番号」と「電話番号：本社」
- 見出しの効き目が届きすぎて「他人の欄」と誤読する（`m.end` で切っている）
- 配布元の様式で結合が抜けている（`addMergeLike` で上下の行に合わせる）

`sweep_labels.py` → `sweep_pick.py` は、この手の抜けを機械で洗い出すためのもの。

## 配布元が様式を差し替えたとき（毎回ゼロから見直さないために）

`.github/workflows/mirror-forms.yml` が**毎日05:00 JST**に様式を取り直し、
中身が変わっていたら自動でコミットする。**誰にも知らせずに変わる**ということ。

自動入力のしかけは様式ごとの決め打ちを一切していない（ファイル名で分岐する箇所は無い）。
セルの結合の幅・字下げ・項目名の言い方といった**形**だけを見て動く。
だから**様式の形が変わらない限り、直したものは直ったまま**で、
新しく増えた様式にもそのまま効く。裏を返すと、**形が変わった様式だけが危ない**。

そこで `tools/autofill_audit.json`（どの様式のどのセルに何が入ったかの控え）を
git に残してある。2回流しても中身は同じなので、比較に使える。

    # 1. 様式が変わったかを見る（forms/ に自動コミットが来ていないか）
    git log --oneline -5 -- forms

    # 2. 変わっていたら、監査を流し直して控えと比べる
    python tools\audit_autofill.py
    git diff tools\autofill_audit.json

差分が出た様式**だけ**を `sweep_render.py <ファイル名の一部>` で紙にして目で見る。
差分が無ければ、様式が変わっても記入結果は変わっていないということなので、何もしなくてよい。

全40様式・142枚を毎回見るのは、**新しく直したときと、様式が変わったときだけ**でよい。
